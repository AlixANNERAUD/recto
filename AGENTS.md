# AGENTS.md

recto is a self-hosted web app to print (CUPS/IPP) and scan (SANE) behind local accounts or
OpenID Connect, written in Rust.

## Layout

| Crate | Role |
| --- | --- |
| `crates/printing` | Print models, the CUPS/IPP client and the CUPS administration client |
| `crates/scanning` | Scan models and the SANE client |
| `crates/authentication` | OpenID Connect sign-in, claims and the cross-site request check |
| `crates/migration` | Database migrations (SeaORM schema builder, SQLite and PostgreSQL) |
| `crates/entity` | Database entities, generated by `mise run entities`, never edited by hand |
| `crates/domain` | Accounts and the database: connect, migrate, back up; `testing` feature for tests |
| `crates/app` | Leptos interface (server-rendered, islands), English and French |
| `crates/frontend` | WebAssembly entry point of the interface |
| `crates/server` | The `recto` binary and library: configuration, commands, routes, sessions, serving |

## Commands

Everything goes through [mise](https://mise.jdx.dev), which pins the toolchain.

| Command | Does |
| --- | --- |
| `mise install` | Installs the pinned tools |
| `mise run format` | Formats the code |
| `mise run lint` | rustfmt check, clippy with `-D warnings` for the server and the WebAssembly frontend |
| `mise run test` | The test suite (nextest) |
| `mise run doc` | Rustdoc with warnings as errors |
| `mise run test-postgres` | The test suite on the PostgreSQL database in `RECTO_TEST_DATABASE_URL` |
| `mise run entities` | Regenerates the entities after a migration changes the schema |
| `mise run check` | What CI runs: lint, rustdoc, tests, cargo-deny |
| `mise run dev` | Development server on http://127.0.0.1:3000 with mocked printers and scanners and a signed-in dev user (debug builds only) |
| `mise run build` | Release binary and site |
| `mise run docs` | The user guide (mdBook, `docs/`) into `docs/book` |
| `mise run sbom` | The CycloneDX SBOM of the server into `crates/server/sbom.json` |
| `mise run coverage` | The test suite with coverage, into `lcov.info` |

Builds are heavy: run one cargo command at a time.

## Rules

- Every interface string goes through `t!`/`tf!`/`tp!` with a key in `crates/app/locales/en.json`
  and its translation in `crates/app/locales/fr.json` (a key missing from either fails the build).
- Print and cancel work without JavaScript (plain forms). Only the scan page and live refresh are
  islands.
- Tests never touch a real printer, scanner or identity provider: use mocks and `wiremock`.
- The user guide in `docs/src` follows Diátaxis (tutorials, how-to guides, reference, explanation).
  A change to settings, pages or behaviour updates the matching pages.
- Comments explain why, never restate the code. Docs are plain, concise English with no em dashes.
- `main` is protected: branch from it, open a pull request and let it merge itself
  (`gh pr merge --auto --squash`) once the required checks, `CI passed` and `Pull request
  title`, succeed. Pull requests are squash-merged, so the title becomes the commit on `main`
  that release-plz reads (see `RELEASING.md`).
- Commits and pull request titles follow Conventional Commits (`feat:`, `fix:`, `test:`,
  `build:`, `ci:`, `docs:`), imperative, with a body. Do not mention AI tools and add no
  `Co-Authored-By` or "Generated with" lines.
