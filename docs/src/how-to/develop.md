# Develop and contribute

recto is written in Rust, with [axum](https://github.com/tokio-rs/axum) for the server and
[Leptos](https://leptos.dev) for the interface. Every tool is pinned and run through
[mise](https://mise.jdx.dev).

## Set up

You need mise, plus libsane and libclang for the libsane bindings. On Debian or Ubuntu:

```sh
sudo apt install libsane-dev libclang-dev pkg-config
git clone https://github.com/AlixANNERAUD/recto.git
cd recto
mise install
```

## Run it

```sh
mise run dev
```

It serves <http://127.0.0.1:3000> and reloads on every change. Every request is signed in as a
development user, an administrator, and the printers and scanners are fakes: three printers in
various states, a few print jobs, and a scanner that scans a sample letter. Its database is
`target/dev.db`, so accounts survive restarts. This mode exists in debug builds only; never expose
that server.

If the build complains about the `wasm-bindgen` version, an older `wasm-bindgen` in
`~/.cargo/bin` is probably shadowing the one mise pins: remove it.

## Check your changes

```sh
mise run format      # format the code
mise run check       # what CI runs: rustfmt, clippy, rustdoc, tests, cargo-deny
mise run test-sane   # scanner tests against SANE's virtual test backend
mise run docs        # build this book into docs/book
```

The tests run on SQLite. To run them on PostgreSQL too, as CI does, point
`RECTO_TEST_DATABASE_URL` at an empty database:

```sh
docker run -d --name recto-test-postgres -p 5432:5432 \
  -e POSTGRES_USER=recto -e POSTGRES_PASSWORD=recto -e POSTGRES_DB=recto postgres:17-alpine
RECTO_TEST_DATABASE_URL=postgres://recto:recto@localhost:5432/recto mise run test-postgres
```

A change to the schema is a new migration in `crates/migration`; `mise run entities` then
regenerates the entities in `crates/entity` from it.

Tests never touch a real printer, scanner or identity provider: the CUPS client and sign-in are
tested against fake servers built with `wiremock`, and scanning against a mock and SANE's `test`
backend.

### Check the printer with ipptool

recto's IPP printer is checked by hand against CUPS's own conformance tests, which need a running
server and Docker, so the test suite does not run them. With `mise run dev` running, create a
device password on the Account page (`http://127.0.0.1:3000/account`), then:

```sh
SECRET=...   # the device password
docker run --rm --network host --entrypoint ipptool olbat/cupsd \
  -t -I -h -T 30 -f /usr/share/cups/data/default-testpage.pdf \
  "ipp://127.0.0.1:3000/device/$SECRET/ipp/print" ipp-everywhere.test
# With Basic credentials, which ipptool takes from the address:
docker run --rm --network host --entrypoint ipptool olbat/cupsd \
  -t -T 30 -f /usr/share/cups/data/default-testpage.pdf \
  "ipp://anyone:$SECRET@127.0.0.1:3000/ipp/print" print-job.test
```

`--network host` makes the container's `127.0.0.1` the host's, from which recto accepts device
passwords over plain HTTP. `-t` prints a report, `-I` goes on after a failure, `-v` shows every
attribute.

The **PWG 5100.14 section 5.1/5.2** block of `ipp-everywhere.test` fails, for expected reasons
only: `image/pwg-raster` and the `pwg-raster-*` attributes (recto does not take rasters yet),
`printer-supply*` (recto has no ink to report, and does not make levels up), and
`overrides-supported WITH-VALUE "document-number"`, a typo in CUPS 2.4's test file that fails
CUPS's own `ippeveprinter` too. Every other test passes. Documents sent this way are held for the
development user, under `target/dev-data/held`.

## Where things are

| Crate | Role |
| --- | --- |
| `crates/printing` | Print models and the CUPS/IPP client |
| `crates/scanning` | Scan models and the SANE client |
| `crates/authentication` | OpenID Connect sign-in and claims |
| `crates/migration` | The database migrations, for SQLite and PostgreSQL |
| `crates/entity` | The database entities, generated by `mise run entities` |
| `crates/domain` | Accounts and the database: users, groups, passwords, backups |
| `crates/app` | The interface, rendered on the server, with islands for the interactive parts |
| `crates/frontend` | The WebAssembly entry point of the interface |
| `crates/server` | The `recto` binary: configuration, commands, routes, sessions, serving |

`AGENTS.md` holds the rules the code follows. Every interface string has a key in
`crates/app/locales/en.json`, which is also where translations start.

## Send a change

Open a pull request against `main`. Commit messages follow
[Conventional Commits](https://www.conventionalcommits.org): `feat:`, `fix:`, `docs:` and so on.

## Release

Releases use [release-plz](https://release-plz.dev). Pushes to `main` keep a release pull request
open with the next version and its changelog; it is the only pull request the maintainer opens.
Merging it tags `vX.Y.Z`, builds the image for amd64 and arm64, publishes it to
`ghcr.io/alixanneraud/recto` (and copies it to Docker Hub when configured) and publishes the
GitHub release. Pushing a tag by hand does the same without a changelog. See `RELEASING.md` in
the repository for the setup.
